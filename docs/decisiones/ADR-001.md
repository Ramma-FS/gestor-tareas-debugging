# ADR-001 — Mantener Expo SDK 57 y el servicio mock

**Fecha:** 25/11/2026  
**Estado:** Adoptada durante el laboratorio.

## Contexto
El proyecto existente utiliza Expo Router, React Native y TypeScript. La consigna pide diagnosticar errores sin rehacer la aplicación. Durante la instalación surgieron conflictos de dependencias peer y el Expo Go del iPhone no era compatible con el SDK del proyecto.

## Decisión
Mantener el SDK y la arquitectura originales. Alinear dependencias con Expo, fijar React DOM y React Test Renderer en 19.2.3 y el preset de Jest de React Native en 0.86.3. Usar React Native Web para verificar el comportamiento en el navegador y conservar el servicio local. Utilizar Jest y TypeScript para regresión y comprobación de tipos.

## Alternativas
- Actualizar el SDK: podría resolver la incompatibilidad con Expo Go, pero introduce cambios ajenos a los defectos del taller.
- Usar un backend real: agrega infraestructura y complejidad innecesarias para el objetivo.
- Usar solo pruebas manuales: no ofrece la misma evidencia repetible que Jest.

## Consecuencias
Se limita el alcance y se conserva la base del profesor. La opción `--legacy-peer-deps` permite instalar pese a conflictos peer, pero exige verificar compatibilidad y reproducibilidad. La ejecución web no valida el comportamiento nativo; queda pendiente Android. Las dependencias y alertas de auditoría deben revisarse antes de distribuir la aplicación.
